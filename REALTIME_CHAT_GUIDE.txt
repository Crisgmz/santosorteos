1. CÓMO FUNCIONA SUPABASE REALTIME
================================================================================

Supabase Realtime utiliza WebSockets para enviar actualizaciones en tiempo real
desde la base de datos a los clientes conectados.

FLUJO DE DATOS:
1. Usuario/Admin inserta un mensaje en la tabla chat_messages
2. PostgreSQL dispara un evento de cambio
3. Supabase Realtime captura el evento
4. El evento se envía a todos los clientes suscritos
5. El cliente recibe el evento y actualiza la UI

EVENTOS DISPONIBLES:
- INSERT: Cuando se inserta un nuevo registro
- UPDATE: Cuando se actualiza un registro
- DELETE: Cuando se elimina un registro
- * (ALL): Todos los eventos anteriores

void _subscribeToMessages() {
  if (_sessionId == null) return;

  _channel = _supabase
      .channel('chat_messages_$_sessionId')
      .onPostgresChanges(
        event: PostgresChangeEvent.insert,
        schema: 'public',
        table: 'chat_messages',
        filter: PostgresChangeFilter(
          type: PostgresChangeFilterType.eq,
          column: 'session_id',
          value: _sessionId,
        ),
        callback: (payload) {
          final newMessage = payload.newRecord;
          
          // Evitar duplicados
          final messageId = newMessage['id'];
          final exists = _messages.any((m) => m['id'] == messageId);
          
          if (!exists && mounted) {
            setState(() {
              _messages.add(newMessage);
            });
            _scrollToBottom();

            // Marcar como leído si es del admin
            if (newMessage['sender_type'] == 'admin') {
              _markMessagesAsRead();
            }
          }
        },
      )
      .subscribe();
}

- Se llama en _initializeChat() después de cargar los mensajes existentes
- Se ejecuta UNA VEZ cuando el usuario inicia el chat
- Permanece activo hasta que se cierra la sesión o la página

A. RECONEXIÓN AUTOMÁTICA
-------------------------

Problema: Si se pierde la conexión, no se reconecta automáticamente.

Solución: Agregar manejo de estados del canal

void _subscribeToMessages() {
  if (_sessionId == null) return;

  _channel = _supabase
      .channel('chat_messages_$_sessionId')
      .onPostgresChanges(
        event: PostgresChangeEvent.insert,
        schema: 'public',
        table: 'chat_messages',
        filter: PostgresChangeFilter(
          type: PostgresChangeFilterType.eq,
          column: 'session_id',
          value: _sessionId,
        ),
        callback: (payload) {
          final newMessage = payload.newRecord;
          final messageId = newMessage['id'];
          final exists = _messages.any((m) => m['id'] == messageId);
          
          if (!exists && mounted) {
            setState(() {
              _messages.add(newMessage);
            });
            _scrollToBottom();

            if (newMessage['sender_type'] == 'admin') {
              _markMessagesAsRead();
              // Opcional: Mostrar notificación
              _showNewMessageNotification(newMessage['message']);
            }
          }
        },
      )
      .subscribe((status, error) {
        if (status == RealtimeSubscribeStatus.subscribed) {
          debugPrint('✅ Suscrito a mensajes en tiempo real');
        } else if (status == RealtimeSubscribeStatus.closed) {
          debugPrint('❌ Canal cerrado, intentando reconectar...');
          // Reintentar suscripción después de 3 segundos
          Future.delayed(const Duration(seconds: 3), () {
            if (mounted && _sessionId != null) {
              _subscribeToMessages();
            }
          });
        } else if (status == RealtimeSubscribeStatus.channelError) {
          debugPrint('❌ Error en el canal: $error');
        }
      });
}

void _subscribeToTypingIndicator() {
  if (_sessionId == null) return;

  _supabase
      .channel('typing_$_sessionId')
      .onBroadcast(
        event: 'typing',
        callback: (payload) {
          if (payload['sender_type'] == 'admin' && mounted) {
            setState(() {
              _adminIsTyping = payload['is_typing'] ?? false;
            });
            
            // Auto-ocultar después de 3 segundos
            if (_adminIsTyping) {
              Future.delayed(const Duration(seconds: 3), () {
                if (mounted) {
                  setState(() => _adminIsTyping = false);
                });
              });
            }
          }
        },
      )
      .subscribe();
}

4. SOLUCIÓN DE PROBLEMAS COMUNES
================================================================================

PROBLEMA 1: Los mensajes no llegan en tiempo real
--------------------------------------------------

CAUSAS POSIBLES:
1. Realtime no está habilitado en Supabase
2. El canal no está suscrito correctamente
3. El filtro de session_id no coincide
4. Problemas de red/firewall

SOLUCIÓN:
1. Verificar en Supabase Dashboard:
   - Database → Replication
   - Asegurarse que chat_messages tiene Realtime habilitado

2. Agregar logs de depuración:

.subscribe((status, error) {
  debugPrint('📡 Estado de suscripción: $status');
  if (error != null) {
    debugPrint('❌ Error: $error');
  }
});

3. Verificar que _sessionId no es null:

debugPrint('🔍 Session ID: $_sessionId');

4. Probar la conexión manualmente:

// En la consola de Supabase SQL Editor:
SELECT * FROM chat_messages 
WHERE session_id = 'TU_SESSION_ID' 
ORDER BY created_at DESC;


PROBLEMA 2: Mensajes duplicados
--------------------------------

CAUSA: El evento INSERT se dispara y también se agrega localmente

SOLUCIÓN: Ya implementada en el código actual con verificación de ID:

final messageId = newMessage['id'];

if (!exists && mounted) {

}


PROBLEMA 3: La conexión se pierde después de un tiempo
-------------------------------------------------------

CAUSA: Timeout de WebSocket o cambio de red

SOLUCIÓN: Implementar heartbeat y reconexión (ver sección 3.A)


PROBLEMA 4: Los mensajes llegan pero no se muestran
----------------------------------------------------

CAUSA: El widget no se está reconstruyendo

SOLUCIÓN: Verificar que se llama setState() y que mounted es true:

if (!exists && mounted) {
  setState(() {
    _messages.add(newMessage);
  });
  debugPrint('✅ Mensaje agregado. Total: ${_messages.length}');
}

void _subscribeToMessages() {
  if (_sessionId == null) return;

  debugPrint('📡 Suscribiéndose a mensajes para sesión: $_sessionId');

  _channel = _supabase
      .channel('chat_messages_$_sessionId')
      .onPostgresChanges(
        event: PostgresChangeEvent.insert,
        schema: 'public',
        table: 'chat_messages',
        filter: PostgresChangeFilter(
          type: PostgresChangeFilterType.eq,
          column: 'session_id',
          value: _sessionId,
        ),
        callback: (payload) {
          debugPrint('📨 Nuevo mensaje recibido: ${payload.newRecord}');
          
          final newMessage = payload.newRecord;
          final messageId = newMessage['id'];
          final exists = _messages.any((m) => m['id'] == messageId);
          
          if (!exists && mounted) {
            setState(() {
              _messages.add(newMessage);
            });
            
            debugPrint('✅ Mensaje agregado. Total mensajes: ${_messages.length}');
            _scrollToBottom();

            // Si es del admin, marcar como leído y notificar
            if (newMessage['sender_type'] == 'admin') {
              _markMessagesAsRead();
              _showNewMessageNotification(newMessage['message']);
              
              // Opcional: reproducir sonido
              // _playNotificationSound();
            }
          } else {
            debugPrint('⚠️ Mensaje duplicado o widget no montado');
          }
        },
      )
      .subscribe((status, error) {
        debugPrint('📡 Estado de suscripción: $status');
        
        if (status == RealtimeSubscribeStatus.subscribed) {
          debugPrint('✅ Suscrito exitosamente a mensajes en tiempo real');
        } else if (status == RealtimeSubscribeStatus.closed) {
          debugPrint('❌ Canal cerrado, intentando reconectar en 3s...');
          Future.delayed(const Duration(seconds: 3), () {
            if (mounted && _sessionId != null) {
              _subscribeToMessages();
            }
          });
        } else if (status == RealtimeSubscribeStatus.channelError) {
          debugPrint('❌ Error en el canal: $error');
        } else if (status == RealtimeSubscribeStatus.timedOut) {
          debugPrint('⏱️ Timeout en la suscripción');
        }
      });
}

9. PREGUNTAS FRECUENTES
================================================================================

P: ¿Los mensajes se reciben si la app está en segundo plano?
R: No, Realtime solo funciona mientras la app está activa. Para notificaciones
   en segundo plano, necesitas implementar Push Notifications.

P: ¿Cuánto tarda en llegar un mensaje?
R: Típicamente menos de 100ms si la conexión es buena.

P: ¿Hay límite de mensajes en tiempo real?
R: Supabase tiene límites según tu plan. El plan gratuito permite 200 
   conexiones simultáneas.

P: ¿Funciona en todos los navegadores?
R: Sí, todos los navegadores modernos soportan WebSockets.

P: ¿Qué pasa si pierdo la conexión a internet?
R: El canal se cierra y debes reconectar. Implementa el manejo de reconexión
   mostrado en la sección 3.A.

P: ¿Puedo recibir mensajes de múltiples sesiones?
R: Sí, pero necesitas suscribirte a cada sesión por separado o usar un filtro
   más amplio.
