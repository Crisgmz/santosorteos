PARTE 2: CONFIGURACIÓN REQUERIDA EN SUPABASE
================================================================================

PASO 1: HABILITAR REALTIME EN LAS TABLAS
-----------------------------------------

1. Ve a: https://app.supabase.com
2. Selecciona tu proyecto
3. Ve a: Database → Replication
4. Habilita Realtime para estas tablas:

   ☐ chat_sessions
      - Marca: INSERT, UPDATE
      
   ☐ chat_messages
      - Marca: INSERT, UPDATE

5. Haz clic en "Save" o "Apply"


PASO 2: VERIFICAR POLÍTICAS RLS
--------------------------------

Ejecuta en SQL Editor (Database → SQL Editor → New query):

-- Política para leer sesiones
CREATE POLICY IF NOT EXISTS "users_can_read_own_sessions" 
ON chat_sessions FOR SELECT
TO authenticated, anon
USING (true);

-- Política para leer mensajes
CREATE POLICY IF NOT EXISTS "users_can_read_messages" 
ON chat_messages FOR SELECT
TO authenticated, anon
USING (true);

-- Política para insertar mensajes como usuario
CREATE POLICY IF NOT EXISTS "users_can_insert_messages" 
ON chat_messages FOR INSERT
TO authenticated, anon
WITH CHECK (sender_type = 'user');

-- Política para que admins puedan insertar mensajes
CREATE POLICY IF NOT EXISTS "admins_can_insert_messages" 
ON chat_messages FOR INSERT
TO authenticated
WITH CHECK (sender_type = 'admin');


PASO 3: VERIFICAR QUE LAS FUNCIONES RPC EXISTEN
------------------------------------------------

Ejecuta en SQL Editor:

-- Verificar funciones
SELECT routine_name 
FROM information_schema.routines 
WHERE routine_schema = 'public' 
  AND routine_name IN (
    'get_or_create_chat_session',
    'send_chat_message',
    'mark_messages_as_read',
    'get_chat_messages'
  );

Deberías ver las 4 funciones listadas.

PARTE 3: CÓMO FUNCIONA EL SISTEMA
================================================================================

FLUJO COMPLETO:
---------------

1. USUARIO ABRE EL CHAT
   - Se ejecuta _toggleChat()
   - Se muestra el popup del chat

2. USUARIO COMPLETA EL FORMULARIO
   - Ingresa nombre, teléfono, email
   - Presiona "Iniciar Chat"
   - Se ejecuta _submitUserInfo()

3. SE INICIALIZA EL CHAT
   - Se ejecuta _initializeChat()
   - Se llama a get_or_create_chat_session()
   - Se obtiene el session_id

4. SE CARGAN MENSAJES EXISTENTES
   - Se ejecuta _loadMessages()
   - Se llama a get_chat_messages()
   - Se muestran mensajes anteriores

5. SE SUSCRIBE A MENSAJES EN TIEMPO REAL
   - Se ejecuta _subscribeToMessages()
   - Se crea un canal de Realtime
   - Se filtra por session_id
   - Se escuchan eventos INSERT

6. USUARIO ENVÍA MENSAJE
   - Se ejecuta _sendMessage()
   - Se agrega mensaje localmente (optimistic UI)
   - Se llama a send_chat_message()
   - El mensaje se guarda en la BD

7. ADMIN RESPONDE
   - Admin envía mensaje desde su panel
   - PostgreSQL inserta el mensaje en chat_messages
   - Supabase Realtime detecta el INSERT
   - El evento se envía al cliente web
   - Se ejecuta el callback en _subscribeToMessages()
   - El mensaje se agrega a la lista
   - Se muestra notificación visual
   - Se marca como leído automáticamente

PARTE 5: SOLUCIÓN DE PROBLEMAS
================================================================================

PROBLEMA 1: Los mensajes no llegan en tiempo real
--------------------------------------------------

SÍNTOMA:
- Envías mensaje desde admin/SQL
- No aparece en la web del usuario
- No hay logs de "💬 Nuevo mensaje recibido"

SOLUCIONES:

1. Verificar Realtime habilitado:
   - Database → Replication
   - chat_messages debe tener toggle verde

2. Verificar suscripción activa:
   - Buscar en consola: "✅ Suscrito exitosamente"
   - Si no aparece, hay un problema de conexión

3. Verificar session_id:
   - El session_id debe ser el mismo en ambos lados
   - Ejecutar en SQL:
     SELECT * FROM chat_sessions ORDER BY created_at DESC LIMIT 1;

4. Verificar políticas RLS:
   - Ejecutar las políticas del PASO 2 de Parte 2

5. Verificar en Chrome DevTools:
   - F12 → Network → WS (WebSocket)
   - Debe haber conexión a: wss://[proyecto].supabase.co/realtime/v1/websocket
   - Estado: 101 Switching Protocols


PROBLEMA 2: Error "function does not exist"
--------------------------------------------

SÍNTOMA:
- Error al iniciar chat
- Error al enviar mensaje
- Logs: "function get_or_create_chat_session does not exist"

SOLUCIÓN:
1. Ejecutar el archivo chat_database.sql completo en Supabase
2. Verificar que las funciones existen (ver PASO 3 de Parte 2)


PROBLEMA 3: Mensajes duplicados
--------------------------------

SÍNTOMA:
- El mismo mensaje aparece dos veces
- Logs: "⚠️ Mensaje duplicado o widget no montado, ignorando"

SOLUCIÓN:
- Esto es normal y está controlado
- El sistema previene duplicados automáticamente
- Si persiste, verificar que no haya múltiples suscripciones


PROBLEMA 4: Notificaciones no aparecen
---------------------------------------

SÍNTOMA:
- Los mensajes llegan pero no se muestra el SnackBar verde

SOLUCIÓN:
1. Verificar que el mensaje es del admin:
   - sender_type debe ser 'admin'

2. Verificar logs:
   - Debe aparecer: "✅ Mensaje agregado a la lista"

3. Verificar que el widget está montado:
   - El método verifica mounted antes de mostrar


PROBLEMA 5: Canal se cierra constantemente
-------------------------------------------

SÍNTOMA:
- Logs: "❌ Canal cerrado, intentando reconectar..."
- Se repite cada 3 segundos

SOLUCIONES:
1. Verificar conexión a internet
2. Verificar que Supabase está operativo
3. Verificar límites de tu plan de Supabase
4. Verificar firewall/proxy no bloquea WebSockets

WHERE status = 'active' 
ORDER BY created_at DESC;

WHERE session_id = 'TU_SESSION_ID'
ORDER BY created_at ASC;

-- Contar mensajes no leídos
SELECT COUNT(*) FROM chat_messages 
WHERE session_id = 'TU_SESSION_ID' 
  AND sender_type = 'user' 
  AND is_read = false;

  id,
  user_name,
  user_phone,
  status,
  created_at,
  last_message_at

PARTE 9: MONITOREO EN PRODUCCIÓN
================================================================================

MÉTRICAS A VIGILAR:
-------------------

1. Tasa de reconexión
   - Buscar: "🔄 Reintentando suscripción"
   - Si es muy frecuente, hay problema de red

2. Mensajes duplicados
   - Buscar: "⚠️ Mensaje duplicado"
   - Debe ser < 1% de mensajes totales

3. Errores de canal
   - Buscar: "❌ Error en el canal"
   - Debe ser 0 en condiciones normales

4. Tiempo de entrega
   - Desde que admin envía hasta que usuario recibe
   - Debe ser < 500ms en condiciones normales


ALERTAS RECOMENDADAS:
---------------------

1. Si tasa de reconexión > 10%
   → Revisar infraestructura de red

2. Si errores de canal > 0
   → Revisar configuración de Supabase

3. Si tiempo de entrega > 2 segundos
   → Revisar carga del servidor
